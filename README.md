# Deep Learning Precipitation Nowcasting (SEVIR + U-Net)

Short-term (20-minute) precipitation nowcasting from radar-derived VIL (Vertically
Integrated Liquid) imagery, using a U-Net trained on the [SEVIR dataset](https://registry.opendata.aws/sevir/)
(Veillette et al., NeurIPS 2020).

![Nowcast comparison](nowcast_comparison.gif)

*Ground Truth vs. Persistence baseline vs. U-Net prediction, across 4 lead times (t+1 to t+4, 5-minute steps).*

## Problem

Given 4 historical radar frames (20 minutes of storm history), predict the next 4
frames (the following 20 minutes). This is framed as an image-to-image regression
task: 4 input channels to 4 output channels, solved with a U-Net.

## Data

- **Source:** [SEVIR](https://registry.opendata.aws/sevir/) (Storm EVent ImageRy), a public,
  unsigned AWS S3 dataset of radar and satellite storm imagery, accessed directly via
  `boto3` and `h5py` (no AWS account required).
- **Subset used:** 10 training storm events and 5 held-out test events, VIL channel only.
- **Not included in this repo:** the raw `sevir_vil_subset.npz` (approximately 33 MB) is
  regenerated by running `step1_data_loading.py`, which pulls directly from the public
  SEVIR S3 bucket. `unet_sevir.pt` (trained weights, approximately 31 MB) is included, so
  Steps 5 and 6 can be run without retraining.
- **Preprocessing:** each 384x384 event is resized to 128x128, with sliding-window
  sampling (4-in, 4-out sequences, stride 4) used to expand a small number of events into
  a workable training set. A log1p transform and normalization are applied to handle
  VIL's extreme skew, since radar imagery is mostly zero (no rain) with rare, high-intensity
  spikes during storms.

## Model

A standard U-Net (approximately 7.8M parameters) with 4 downsampling and 4 upsampling
blocks, skip connections at every resolution, and a sigmoid output activation (targets
are normalized to [0,1]). The model is trained with a weighted MSE loss, where each
pixel is weighted by its target intensity (`weight = 1 + 9 * target`). This weighting
was necessary to prevent the model from converging to the trivial solution of predicting
no rain everywhere, a common failure mode when training on heavily imbalanced
precipitation data.

## Evaluation

Standard meteorological verification metrics are computed against a persistence
baseline, which copies the last observed frame forward as its forecast. Persistence is
a strong baseline at short lead times, since the atmosphere changes relatively little
over a few minutes.

- **POD** (Probability of Detection): of the times it actually rained, how often did the model catch it?
- **FAR** (False Alarm Ratio): of the times the model predicted rain, how often was it wrong?
- **CSI** (Critical Success Index): an overall skill score that accounts for both misses and false alarms, unlike accuracy, which is inflated by the class imbalance between rain and no-rain pixels.

Rain/no-rain threshold: VIL byte value of 74 or higher (the convective-storm threshold used in SEVIR benchmark literature).

### Results

**Overall, pooled across all 4 lead times:**

| Metric | U-Net | Persistence |
|--------|-------|-------------|
| POD    | 0.812 | 0.713       |
| FAR    | 0.341 | 0.291       |
| CSI    | **0.572** | 0.551   |

**CSI by lead time (the more informative view):**

| Lead time | U-Net CSI | Persistence CSI | U-Net wins? |
|-----------|-----------|------------------|-------------|
| t+1 (5 min)  | 0.601 | **0.703** | No  |
| t+2 (10 min) | **0.621** | 0.579 | Yes |
| t+3 (15 min) | **0.564** | 0.501 | Yes |
| t+4 (20 min) | **0.514** | 0.445 | Yes |

**Takeaway:** persistence performs best at the shortest lead time (t+1), where the
atmosphere has barely changed, a pattern well documented in the nowcasting literature.
The U-Net overtakes persistence from t+2 onward, and its relative advantage grows with
lead time as storms evolve in ways a simple copy-forward forecast cannot capture.
Overall CSI favors the U-Net by 3.7%.

## Known limitations

- Trained on a small subset (10 events, 5 epochs) as a proof of concept. A production
  model would use the full SEVIR dataset and substantially more training.
- Evaluated on only 5 held-out storms; metrics would be more stable with a larger test set.
- The rain/no-rain threshold (byte value 74) and loss weighting (rain_weight = 9) are
  hand-tuned choices rather than the result of a formal hyperparameter search.

## Running it

Note: these scripts were built and run in Google Colab, so the `__main__` blocks use
hardcoded `/content/...` paths. When running locally, either work from a `/content`
directory or edit the paths at the bottom of each script to point to a location of your
choice.

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. Download and process data 
python scripts/step1_data_loading.py

# 3. Train the model (optional, since unet_sevir.pt is already included)
python scripts/step4_train.py

# 4. Evaluate the model
python scripts/step5_evaluate.py

# 5. Generate the visualization GIF
python scripts/step6_visualize.py
```
