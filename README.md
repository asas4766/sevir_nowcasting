# Deep Learning Precipitation Nowcasting (SEVIR + U-Net)

Short-term (20-minute) precipitation nowcasting from radar-derived VIL (Vertically
Integrated Liquid) imagery, using a U-Net trained on the [SEVIR dataset](https://registry.opendata.aws/sevir/)
(Veillette et al., NeurIPS 2020).

![Nowcast comparison](nowcast_comparison.gif)
*Ground Truth vs. Persistence baseline vs. U-Net prediction, across 4 lead times (t+1 to t+4, 5-min steps).*

## Problem

Given 4 historical radar frames (20 minutes of storm history), predict the next
4 frames (the following 20 minutes). This is framed as an image-to-image
regression problem: 4 input channels → 4 output channels, solved with a U-Net.

## Data

- **Source:** [SEVIR](https://registry.opendata.aws/sevir/) (Storm EVent ImageRy), a public,
  unsigned AWS S3 dataset of radar/satellite storm imagery. Accessed directly via
  `boto3` + `h5py` (no AWS account required).
- **Subset used:** 10 training storm events, 5 held-out test events, VIL channel only.
- **Not included in this repo:** the raw `sevir_vil_subset.npz` (~33 MB) is regenerated by
  running `step1_data_loading.py`, which pulls directly from the public SEVIR S3 bucket
  (no AWS account needed, takes a few minutes). `unet_sevir.pt` (trained weights, ~31 MB)
  *is* included, so you can jump straight to Step 5/6 without retraining.
- **Preprocessing:** each 384x384 event resized to 128x128, sliding-window sampling
  (4-in/4-out sequences, stride 4) to expand a handful of events into a workable
  training set, log1p transform + normalization to handle VIL's extreme skew
  (radar imagery is mostly zero/no-rain with rare intense spikes).

## Model

Standard U-Net (~7.8M parameters): 4 downsampling / 4 upsampling blocks with skip
connections at every resolution, sigmoid output activation (targets are normalized
to [0,1]). Trained with a **custom weighted MSE loss** — pixels are weighted by
their target intensity (`weight = 1 + 9 * target`), which was necessary to stop the
model from collapsing to the trivial "predict no rain everywhere" solution, a classic
failure mode on this kind of heavily skewed data.

## Evaluation

Standard meteorological verification metrics, computed against a **persistence
baseline** (naively copying the last observed frame forward — a notoriously strong
baseline at short lead times):

- **POD** (Probability of Detection): of the times it actually rained, how often did the model catch it?
- **FAR** (False Alarm Ratio): of the times the model predicted rain, how often was it wrong?
- **CSI** (Critical Success Index): overall skill score; unlike accuracy, it isn't inflated by the "mostly no rain" class imbalance.

Rain/no-rain threshold: VIL byte value ≥ 74 (the convective-storm threshold used in the SEVIR benchmark literature).

### Results

**Overall (pooled across all 4 lead times):**

| Metric | U-Net | Persistence |
|--------|-------|-------------|
| POD    | 0.812 | 0.713       |
| FAR    | 0.341 | 0.291       |
| CSI    | **0.572** | 0.551   |

**CSI by lead time** (the more informative view):

| Lead time | U-Net CSI | Persistence CSI | U-Net wins? |
|-----------|-----------|------------------|-------------|
| t+1 (5 min)  | 0.601 | **0.703** | no  |
| t+2 (10 min) | **0.621** | 0.579 | yes |
| t+3 (15 min) | **0.564** | 0.501 | yes |
| t+4 (20 min) | **0.514** | 0.445 | yes |

**Takeaway:** persistence wins at the shortest lead time (t+1), where the
atmosphere genuinely hasn't changed much yet — this is expected and well
documented in the nowcasting literature. The U-Net overtakes persistence from
t+2 onward and its relative advantage grows with lead time, as storms evolve in
ways a naive "copy forward" can't capture. Overall CSI favors the U-Net by 3.7%.

## Known limitations

- Trained on a small subset (10 events, 5 epochs) to fit a 1-day build — a
  production model would use the full SEVIR dataset and substantially more
  training.
- Evaluated on only 5 held-out storms; metrics would tighten with a larger test set.
- The rain/no-rain threshold (byte ≥ 74) and loss weighting (rain_weight=9) are
  simple, hand-tuned choices rather than the result of a hyperparameter search.

## Repo structure

```
step1_data_loading.py   # Pulls a small VIL subset directly from the public SEVIR S3 bucket
step2_dataset.py        # PyTorch Dataset: sequencing, log-transform normalization, resizing
step3_unet.py           # U-Net architecture (4 in -> 4 out channels, skip connections)
step4_train.py          # Training loop with weighted MSE loss
step5_evaluate.py       # POD/FAR/CSI evaluation vs. persistence baseline, per lead time
step6_visualize.py      # Generates the GIF comparison above
unet_sevir.pt           # Trained model weights (~31 MB, included)
metrics.json            # Full evaluation results
nowcast_comparison.gif  # Ground Truth vs Persistence vs U-Net visualization
```

## Running it

> **Note:** these scripts were built and run in Google Colab, so the `__main__` blocks
> use hardcoded `/content/...` paths. If running locally, either work from `/content`
> (e.g. `mkdir -p /content && cd /content` first) or edit the paths at the bottom of
> each script to point wherever you'd like your data/model to live.

```bash
pip install boto3 h5py pandas numpy torch imageio matplotlib

python step1_data_loading.py   # only needed if you don't already have sevir_vil_subset.npz
python step4_train.py          # step2/step3 are imported, not run standalone
python step5_evaluate.py
python step6_visualize.py
```

Since `unet_sevir.pt` is already included in this repo, you can skip straight to
`step5_evaluate.py` / `step6_visualize.py` without retraining -- you'll just need
`sevir_vil_subset.npz`, which requires rerunning Step 1 first (it isn't committed here).
